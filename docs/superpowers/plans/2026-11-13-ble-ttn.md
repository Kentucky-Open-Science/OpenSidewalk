# BLE to TTN Implementation Plan

> **For agentic workers:** Implement this plan natively with the executing-plans
> and test-driven-development skills; perform a final independent review.

**Goal:** Connecting an iPhone to KG100S produces a connection event on TTN.

**Architecture:** A connectable BLE peripheral puts fixed-size events in a
bounded queue. The existing LoRaWAN loop consumes events after joining and
preserves an event on send failure. FPort 3 is decoded separately from telemetry.

**Tech Stack:** Zephyr 4.5.0, Silicon Labs controller, C, JavaScript decoder.

**Spec:** `docs/superpowers/specs/2026-11-13-ble-ttn-design.md`

## Global Constraints

- Retain NVS credentials/nonce and USERDATA; no mass erase.
- One BLE client; eight queued events; 30 seconds between event attempts.
- FPort 3, 11 bytes, schema/event/sequence/address type/address.
- Continue existing FPort 2 telemetry and automatic OTAA.

## Review Focus

- Connection callback cannot block on RF or lose the pending queue head.
- Queue full must count drops rather than overwrite old events.
- Failed TX and reconnects must retain ordering and resume advertising.
- Image bounds must exclude credential and factory storage.
- Device-specific data and new vendor binary notices must stay correct.

## Progress

Baseline: existing host suite passed; live board ready and joined to TTN.
The user requested proceeding with a simple connection event, so implementation
does not wait for additional Bluetooth profile choices.

Task 1: complete. Decoder first failed because FPort 3 was unsupported; queue
test then failed on missing functions. Implementation passes the full host suite.

Build finding: the older cached Zephyr checkout has a different prototype RF
patch. A separate detached checkout of the same pinned commit is used, preserving
that checkout. BLE additionally needs the pinned Mbed TLS / TF-PSA modules;
the manifest allowlist now includes these dependencies.

Task 2: complete. Final pinned build passes, using 284,432 FLASH bytes and
44,080 RAM bytes. Image checksums/BIN agreement and credential partition bounds
pass. The pinned LoRaWAN send API flushes pending MAC commands itself and
returns -EAGAIN; those events remain queued rather than bypassing that API.

Task 3: real Mac connection and GATT read, TTN decoded event, reconnect/queue
spacing and preserved-profile automatic OTAA verified. Firmware hashes/notices,
user instructions, release boundaries and full host suite pass. Independent
read-only review found no Critical, Important or material Minor issues. The
actual iPhone connection remains the user's device test.
